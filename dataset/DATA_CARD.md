# Dataset Card: Meridian Assist

This card documents every data source used to build and demonstrate Meridian Assist, per
PROJECT_PLAN Section 4. Regenerate the entire pipeline from a clean clone with `make data`
(equivalent to running `dataset/scripts/download.py`, `build_catalog.py`, `build_nhtsa.py`,
`build_intents.py`, `generate_synthetic.py`, `load_db.py`, and `embed_kb.py` in that order).

## Regeneration

```
make data
```

runs the pipeline end to end: `download -> build_catalog -> build_nhtsa -> build_intents ->
generate_synthetic -> load_db -> embed_kb`. Each step is also runnable independently; see
`Makefile` targets `data-download`, `data-catalog`, `data-nhtsa`, `data-intents`,
`data-synthetic`, `data-load`, `data-embed`.

## Processed Tables

| File | Built by | Description |
|---|---|---|
| `processed/vehicle_catalog.parquet` | `build_catalog.py` | EPA vehicles filtered to model year 2010+, top 15 US makes by row count, with an `nhtsa_model_name` column cross-checked against NHTSA vPIC `GetModelsForMake`. |
| `processed/recalls_subset.parquet` | `build_nhtsa.py` | NHTSA recall campaigns from 2014 onward, filtered to catalog makes: campaign number, make, model, model year, component, summary, consequence, remedy, report date. |
| `processed/complaints_monthly.parquet` | `build_nhtsa.py` | NHTSA owner complaints aggregated by make, model, model year, component, and month: count, crash flag count, fire flag count, injured count. |
| `processed/intent_train.parquet`, `intent_val.parquet`, `intent_test.parquet` | `build_intents.py` | Stratified 80/10/10 split of the intent training set (automotive-seeded utterances + Bitext rows mapped onto the automotive taxonomy). |
| `processed/kb_chunks_preview.parquet` | `embed_kb.py` | Knowledge base split into heading-based sections and 220-380 word chunks (approximating 300-500 tokens with 50-token overlap), with a content hash for incremental re-embedding. |

## NHTSA Flat File Field Mapping

Both flat files are TAB-delimited with no header row. Field positions were taken directly from
the data dictionaries shipped next to the zips (`RCL.txt`, `CMPL.txt`), not guessed:

- `FLAT_RCL_POST_2010.zip`: field 2 CAMPNO, field 3 MAKETXT, field 4 MODELTXT, field 5 YEARTXT,
  field 7 COMPNAME, field 13 ODATE, field 16 RCDATE, field 20 DESC_DEFECT, field 21
  CONEQUENCE_DEFECT, field 22 CORRECTIVE_ACTION.
- `FLAT_CMPL.zip`: field 4 MAKETXT, field 5 MODELTXT, field 6 YEARTXT, field 7 CRASH, field 9
  FIRE, field 10 INJURED, field 11 DEATHS, field 12 COMPDESC, field 17 LDATE (date complaint
  received, used for monthly bucketing).
- Dates are `YYYYMMDD`; recall and complaint date fields use different underlying formats in
  the live API (`DD/MM/YYYY` vs `MM/DD/YYYY`) but the flat files are consistently `YYYYMMDD`.
- Both files are filtered to model year 2014+ and to the top-15 catalog makes before further
  processing, to keep the demo dataset focused and the complaint aggregation tractable.

## Synthetic Data (D7)

Generated by `generate_synthetic.py` with `numpy`/`Faker` seeded at `20260924`, covering the 36
months ending the current month. Business rules implemented (see `synthetic_rules.py` for the
pure, unit-tested math):

- ~18,000 customers, ~24,000 vehicles, ~60,000 repair orders across 3 locations and 34 bays.
- 7-9% YoY repair-order growth, January labor rate increases, 3% yearly parts inflation.
- Spring/fall seasonality, Saturday-busiest weekly pattern, Sunday closed, December dip.
- Pay-type mix: 70% customer pay, 18% warranty, 7% recall (linked to real campaigns from
  `recalls_subset` matching the vehicle's make and model year), 5% internal.
- No-show rate 6-9% (higher for bookings made more than 14 days out), 5% cancellations, 22%
  upsell rate, ARO trending from ~$310 to ~$365 across the window.
- Conversations start 12 months before the data's end date (assistant launch), channel split
  75% chat / 25% voice, containment ramping from 58% to 78%.

Only `dataset/synthetic/*_sample.csv` (first 100 rows of each table) and `*_sample.csv` for the
JSONL tables are committed to source control; the full synthetic tables are gitignored and
regenerated by `make data`.

## Known Limitations

- The public NHTSA recall API reports campaigns by year/make/model, not per-VIN completion
  status; VIN lookups are decoded through vPIC and the assistant must direct customers to
  confirm exact completion status with the service desk (see `docs/CUAD_INTEGRATION_PLAN.md`
  and `dataset/reference/knowledge_base/recall-process.md`).
- The Bitext dataset's dedicated automotive vertical is a separate commercial product; this
  project instead authors automotive-specific seed utterances and augments them
  programmatically (see `build_intents.py`).
- `load_db.py` bootstraps a minimal schema sufficient for the data pipeline's own tables. The
  authoritative identity, RBAC, and analytics schema is defined by the Phase 2 Alembic
  migrations; once those exist, `load_db.py` loads into them unchanged (it only issues
  `CREATE TABLE IF NOT EXISTS`).
- `embed_kb.py` chunks and previews the knowledge base without a live database or model; the
  embedding and pgvector upsert steps are skipped gracefully until Phase 2 (database) and
  Phase 3 (embedding model) exist, and re-run automatically once `DATABASE_URL` and
  `sentence-transformers` are available.
